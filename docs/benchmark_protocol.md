# Benchmark protocol (M7)

This document fixes what `benchmark.py` measures and how results may be worded. Results are
**Observed**: one dataset, one protocol. They prove nothing and are never entered in the
"Proven" column of `traceability.md`.

## Status of this protocol

The protocol below is what `benchmark.py` already implemented before this document existed. It
was therefore **not pre-registered** in the strict sense: the earlier numbers in `math.tex` §5 were
produced before it was written down. From this commit on, any change to the constants in
`benchmark.py` (`ETA`, `MEM`, `FLOOR`, `LR_SCALES`, `FACTORS`, split and seed lists) is a protocol
change and must be recorded here, with the date and the reason, before the final run.

## Design

| Item | Setting |
| --- | --- |
| Dataset | scikit-learn `digits`, class-incremental, five experiences, degree-3 polynomial features |
| Validation views | splits 100-103; training part cut 80/20, stratified by class, before standardisation; statistics from fitting rows only |
| Test splits | 0-9 (10 independent splits), 2 training seeds each (seeds 1, 2), seed-averaged within a split |
| Replay memory | 60 and 100 per class |
| Methods | ordinary SGD; smaller-learning-rate controls (x0.75, 0.5, 0.35, 0.25); exact `strategy_b`; relaxed `strategy_b` (12 candidates: tol 0.3/0.1/0.03/0.01 x beta 0/0.1/0.3); degree control, one degree at a time, factors 0/0.05/0.1/0.25/0.5/0.75 |
| Selection | relaxation: highest validation accuracy among candidates with validation forgetting at most 70 % of ordinary SGD's. Degree control: acquisition floor 0.5, Pareto front of (accuracy, forgetting), maximise accuracy - forgetting. All on validation views only |
| Test use | each configuration is evaluated on the test splits after selection; test numbers never feed selection |
| Metrics | `acc`, `forgetting`, `plasticity`, `newest`, `old`, and arrival accuracy per experience |
| Statistics | paired 95 % t-interval of the per-split differences (10 splits). The interval reflects between-split variability after seed-averaging |
| Accuracy criterion (relaxed variant) | verdict `VALUE` iff the lower bound of the paired accuracy interval vs ordinary SGD is above -0.01 and the upper bound of the paired forgetting interval is below 0 |

## Reproducibility

```bash
python benchmark.py --out results/benchmark_raw.json     # runs everything, writes raw per-split results
python benchmark.py --report results/benchmark_raw.json  # reprints the full console output from the raw file
```

`report()` is the only code that prints results. `main()` builds the raw dictionary and then calls
`report()` on it, so `--report` reproduces every line of the run that wrote the file: the
validation selection of the relaxation, both memory sizes (method table, paired comparisons,
learning-rate frontier and verdict) and the degree-control study (validation feasibility counts,
selected candidate or `None`, and the paired test comparison when a candidate was selected). No
model is retrained by `--report`.

The raw file holds per-split metric lists for every configuration plus `provenance` (git commit,
dirty flag, Python/NumPy/SciPy/scikit-learn versions, protocol constants). Runs are deterministic
given the split and training seeds.

### Which results count

Only results generated by the benchmark workflow from a committed revision count. A raw file is
accepted as evidence only if its `provenance` has `dirty: false` and a `commit` equal to the
revision that is being reported. Raw files produced on a developer machine from an uncommitted
tree are not committed. No raw results are checked in until the workflow has produced them.

## Deviations from the verification plan (stated, not hidden)

1. **Seeds.** The plan asked for at least 10 seeds per configuration. This protocol uses 10 splits
   x 2 training seeds (20 runs). The confidence interval is over the 10 splits, so training-seed
   variability is not estimated separately.
2. **Second dataset.** The plan asked for at least one further dataset. None is added: the
   development environment had no network access, and `digits` is the only class-incremental
   image dataset bundled with scikit-learn. Every claim is therefore a `digits` claim.
3. **External baselines** (replay-only variants, EWC and similar) are not implemented. No
   comparison with other continual-learning methods is made or implied.
4. **Bootstrap intervals** are not used; the paired t-interval of the existing protocol is kept.

## Status of the evidence

The results are preliminary, `digits`-only observations (10 split-level means, 2 training seeds
each). They do not complete the original M7 plan. The degree-control study shows no demonstrated
benefit under this protocol: for ordinary SGD the selected control was tested, and for
`strategy_b` and the relaxed update no candidate met the validation acquisition floor. That is
not evidence that degree control can never help.

## Allowed wording

| Allowed | Not allowed |
| --- | --- |
| "On `digits` under this protocol the strict step changed average forgetting by a mean of a (95 % CI [l, u]) relative to ordinary SGD." | "The method prevents forgetting." |
| "The relaxed variant met the accuracy criterion at memory X and did not at memory Y." | "The relaxed variant improves the trade-off" without stating where. |
| "Degree control showed no measurable benefit under this protocol." | Omitting the null result. |
| "Lean proves reference preservation for the exact update; the implementation preserves it up to the tested residual." | "Lean proves the method works." |
